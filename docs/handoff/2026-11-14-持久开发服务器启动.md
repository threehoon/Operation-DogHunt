# 持久启动开发服务器

日期：2026-11-14（Asia/Shanghai）
状态：✅完成

## 目标与做法

用户要求打开前后端开发服务器。项目使用 `make backend` 启动 FastAPI（`127.0.0.1:8000`），使用 `make frontend` 启动 Vite（`127.0.0.1:5173`）。本轮检查发现两个端口都没有服务；此前直接在工具运行会话里启动，下一轮对话时服务已退出。

尝试使用 `nohup make backend` 和 `nohup make frontend` 放到后台，命令返回后进程仍退出，日志仅留下启动命令，两个端口未监听。随后改用系统自带 `screen` 创建两个 detached 会话，名称分别为 `doghunt_backend` 与 `doghunt_frontend`。这两个会话在启动命令结束后仍存在，端口监听正常。以后接手先检查实际进程和端口，不根据本记录推断服务器始终运行。

## 实际验证

- `screen -ls` 显示 `doghunt_backend`、`doghunt_frontend` 两个 detached 会话。
- `lsof` 显示 `127.0.0.1:8000` 和 `127.0.0.1:5173` 均有监听进程。
- `http://127.0.0.1:8000/api/v1/health`、`http://127.0.0.1:5173/welcome`、`http://127.0.0.1:5173/api/v1/health` 均返回 HTTP 200。

未修改业务代码、配置或代码地图，未调用真实模型或刷新外部盘口。可用 `screen -r doghunt_backend` 或 `screen -r doghunt_frontend` 查看对应终端；在会话内按 Ctrl+C 停止服务。
