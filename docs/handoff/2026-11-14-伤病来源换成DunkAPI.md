# 伤病来源换成 DunkAPI

日期：2026-11-14（Asia/Shanghai）
状态：⚠️ 代码、测试、提示词与记录已完成，真实取数一次；未提交，未调用模型，后端未重启。接在[整季实力分与 DunkAPI 球队效率](2026-11-14-整季实力分与DunkAPI球队效率.md)之后。

## 起因

ESPN 伤病接口无文档、条款未核实。用户决定换成 DunkAPI，接受它没有报告时间和短评。

## 改动

- `services/odds/injuries.py` 重写：调用 `get_injuries`（2 credits），4 小时内不重复，缩写（GS、NO、NY、SA、UTAH、WSH）对到全名。
- 新伤病判断改到服务端：每次保存时和上一份 DunkAPI 快照比对，记下每人当前状态的 `listed_since`（最早采集到）和 `listed_after`（上一份还没列出时的采集时间）。聊天时按该队最后一场的东部日期给出 `new_since_last_game`：true 新伤病、false 已在战绩里、null 无法判断。
- `odds_context` 先算 `team_form`，再交给伤病，每队带 `last_game`。
- 提示词：sources_v5、odds_v6、method_v7、output_v5；null 时只说明，不作选边理由；球员作用只能用 C 级。静态提示词 7599 → 7837 字。记录 CHANGELOG、I-007、README，E-010、E-011 期望改为 DunkAPI；D-001 伤病样例改格式。
- 三个取数模块的保存时间改用传入的 `now`（测试不再依赖真实时钟）。
- `integrations/espn.py` 已不被引用，用户确认后已删除（删除后 106 项测试仍通过）。

## 验证

- `cd backend && .venv/bin/python -m unittest discover -s tests`：106 项通过（连跑 3 次）；`prompt check` 通过。
- DunkAPI 真实取伤病一次：28 队 100 人，报告日 2026-11-14；账本累计 14 credits。
- 同时只读取了 ESPN 一次做对比：也是 28 队 100 人，人名完全相同。推测 DunkAPI 的伤病来自 ESPN，未核实。
- 补取 BALLDONTLIE 赛程（188 场，183 场有比分）后，用真实数据拼出掘金 @ 鹈鹕的聊天输入：两队 `last_game` 为 11-11、11-13；第一份 DunkAPI 快照里所有人 `new_since_last_game` 为 null，符合设计。

## 未验证与风险

- 未调用真实模型，E-010、E-011、E-012 未试跑；运行中的后端要重启才用新代码和新提示词。
- 第一份快照全部 null，要等之后再更新盘口（间隔 4 小时以上）才可能出现 true；两次更新间隔越长，null 越多。
- 没有短评，模型不知道球员在队中的作用。
- 4 小时内不重复取，开赛前的临时变化可能晚到。
- DunkAPI 和 ESPN 人名完全一致，换的是提供方和条款，数据可能同源。
