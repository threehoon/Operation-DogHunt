## 目标与结果

用户要求在 `docs/` 下建立专门目录，整理项目 API 地址，并创建地址变更时同步维护该目录的 Skill。

- `docs/api/README.md`：以当前工作区源码为依据，集中记录模型中转、The Odds API、BALLDONTLIE、DunkAPI 四类外部服务，列出 DunkAPI 的具体工具路径并区分在用和仅适配层允许。另记录六个后端业务接口、两个接口说明地址、前端代理、配置与认证变量位置及触发方式。
- `.agents/skills/api-address-maintenance/SKILL.md` 与 `agents/openai.yaml`：指导后续 AI 从地址定义追踪实际调用方，同步清单、相关现行说明和必要的本机记录。
- `AGENTS.md`：已加入相关地址、路由、端口和代理目标变化后调用 Skill 的规则。手动改文件后可显式调用 `$api-address-maintenance`；Skill 不在后台监听，也不能自动发现供应商自身的变更。
- `README.md` 与 `CODEBASE.md`：加入统一清单入口。按 codebase-map 核对相关调用位置，本次只加导航，不改变业务行为，不刷新各模块核对日期或历史验证。

基准：Git HEAD `ed9c1cf` 加当前未提交工作区。开始时已有后端、提示词、代码地图、配置示例及交接等大量改动；本次保留原有改动，仅对上述文件及交接索引作增量修改。未提交、未推送。

## 为什么这样组织

共享仓库原有模型中转地址使用 `https://relay.example` 脱敏占位符，不能当成真实可连接地址。本次公共清单记录 `DOGHUNT_MODEL_BASE_URL` 与 `/responses` 拼接规则，真实值只从本项目 `backend/.env` 定向提取，记录在 `docs/api/local-addresses.local.md`。该文件已加入 `.gitignore`，不含 Key，不随克隆共享。它只代表配置文件快照，运行环境变量可覆盖，未据此声称运行进程已采用该地址。

该设计既让本机使用者能查到实际模型地址，也延续仓库已有脱敏约定；其他人克隆项目时，需要配置自己的模型地址并调用 Skill 生成本机记录。没有读取其他应用配置。

当前源码中 ESPN 适配层已删除、伤病改用 DunkAPI，不能沿用旧交接中的 ESPN 在用结论。`get_standings` 仅在 DunkAPI 允许名单中，当前没有业务调用，清单单独标明。历史交接保持原貌，没有批量替换历史地址。
