# 聊天超时排查与断连修复

日期：2026-11-14（Asia/Shanghai）
状态：⚠️代码已修，运行环境未修

用户反馈网页提问总是等到超时。最初判断为 `high` 思考强度太慢，经实测推翻：请求根本没有发到模型。

## 原因

启动 8000 后端的终端里，`NO_PROXY` 含 `::1/128`。httpx 0.28.1 创建客户端时抛 `httpx.InvalidURL: Invalid port: ':1'`。这个异常不在 `llm.py` 原来捕获的类型里，`/chat/stream` 发完 200 响应头后连接直接断开，没有 error 事件。经 Vite 转发时浏览器收不到断开，只能等前端超时。与 [后端 API 调用检查](2026-11-14-后端API调用检查.md) 和 [网络修正验证](2026-11-14-网络修正验证与免费数据缺口.md) 记录的是同一个问题。

## 本次改动

- `backend/.env`：思考强度 `high` → `medium`，超时 120 → 240 秒（用户同意“改配置并实测”）。
- `backend/app/integrations/llm.py`：捕获 `httpx.InvalidURL`，返回 503，提示检查代理环境变量并重启后端。
- `backend/app/services/chat/service.py`：事件流开始后任何未预期异常都转成 error 事件（500），日志只记类型。
- `backend/tests/test_chat.py`：新增 3 项测试。
- 代码地图：后端子块与 `CODEBASE.md`。
