# 前端界面样式统一

日期：2026-11-14（Asia/Shanghai）
状态：✅完成本地实现与截图核对；已提交并推送到 `liwangcc/Operation-DogHunt` 的 `dev`，随 PR #7 交给 `threehoon/dev`。

## 使用者的要求

拉取仓库最新版本，完成全部前端样式；保留全息感觉，不要太重的“AI 味”和浮躁感，界面要给人运筹帷幄的感觉；改完只在本地提交，后续工作由 Hermes 接手。

## 做了什么

先把本地 `dev` 快进到 `origin/dev` 的 `41227b3`（14 个提交，本地没有分叉），再在它上面做样式。

只动样式层：`frontend/src/styles/` 的两份全站样式、内页外壳和全部内页组件的样式块、启动页界面层的样式、`shell/backdrop.ts` 着色器里的数值、`index.html` 的首屏底色。页面结构、数据、接口和 3D 场景本体没有变。

取向是“一间安静的暗室，数据是投在上面的冷光”：

- 底色从深蓝改为接近墨色，强调色从高饱和的青改为更淡的冷光，提醒色改为黄铜色。变量名（`--cyan`、`--amber` 等）没有改，别处引用不受影响。
- 去掉外发光、渐变字、斜体超粗数字、斜切色块和英文装饰眉题；眉题改成“序号 + 工位名”。
- 去掉循环的闪烁、呼吸、传球、扫光，以及悬停位移和逐个升起的入场；只留倒计时、等待计时这类承载信息的变化。
- 全息感留在几处：聊天起始画面的静态战术板、比赛页“下一场开赛”的主投影、统计页的累计曲线面板、重要面板四角的定位标记。
- 读数统一用仪表感的数字字体（Windows 上是 Bahnschrift）；记录、统计、设置三页各有一组四张卡片并成了一条“仪表带”。
- 动态背景放慢、调暗、压到页面最上面一条；启动页的标题和按钮去掉发光。

完整的规则和逐项说明在[前端子块](../codebase/frontend.md)的“界面样式”一节。

模板的改动只有：眉题文字、两个按钮的类名（`btn--primary` → `btn--solid`，聊天“发送”和“下一场开赛”的“交给 AI 分析”）、起始画面全息球场和等待卡片的装饰图形、侧栏与启动页标题里的一个装饰色块。脚本逻辑只有统计页三个曲线颜色值跟着色板换了。

## 边界与需要接手的人留意的地方

- 接口全部是模拟的，没有连真实后端，没有调用模型或刷新盘口。
- 这一轮没有改脚本逻辑，所以没有逐项重测键盘操作、CSV 导出、偏好保存等交互；3D 场景和比赛没有重测，只确认启动页界面层显示正常。

## 验收后的修改：累计盈亏图

使用者打开页面验收时提出，统计页的折线图难查阅，希望更容易读出信息。这一项改了图的画法和交互，不只是样式，单独提交。

原图的问题：三条阶梯线（当前筛选、让分、大小分）叠在同一块区域里；不悬停读不到任何数；同一天的几场结算会画出细小的尖刺；样式统一时把线色调淡后，用配色校验脚本查出三色在深色底上明度过高、彩度过低，其中两条的色差低于正常视力的下限。

现在的做法：整体只画一条线，让分和大小分拆成下方两张小图，每张图一条线，靠标题区分；曲线按结算日累计；零线上下分别铺很淡的绿和红；图上方直接给出期末、最高、最低、最大回撤和已结算次数，期末与极值点标在线上；悬停或方向键逐天查看，一个提示框列出各条线截至当天的累计和当天结算的记录。完整说明在前端子块的“累计盈亏图”一节。

需要留意：

- 图上的“最低”“最大回撤”按结算日计，不含某一天中途的更低点；换成逐条口径数值会不同。这是为了去掉假尖刺做的取舍，使用者尚未就这一点表态。
- 小图的纵轴刻度和上图不同（两张小图彼此相同），图下方有一行说明。
- 数据仍是演示记录；`domain/metrics.ts` 没有改。没有用读屏软件和触屏实机试过。

## 踩过的坑

- Git Bash 会把以 `/` 开头的命令行参数改写成 Windows 路径，给脚本传路由时不要带开头的斜杠。
- 无头 Edge 在 2 倍像素密度下用“裁剪区域”截图，带三维变换的元素会显得又暗又糊；整页截图是正常的。看到这种图先换整页截图确认，不要当成样式问题去改。
- 同一个无头浏览器连续打开多个带 WebGL 背景的页面偶尔会卡死，每张图换一个新的浏览器进程更稳。

截图脚本和截图都是临时产物，放在 `frontend/node_modules/.cache/` 下，核对完已删除。
